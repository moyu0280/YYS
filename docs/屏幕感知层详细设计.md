# 屏幕感知层详细设计

> 目标：把任意一帧画面变成可决策的 ScreenState，是 Agent 的"眼睛"。
> 原则：默认最便宜，按需升级——能上 UI 树就不上 OCR，能 OCR 就不上 VLM。

---

## 1. 三级感知（成本递进）

| 级 | 手段 | 成本 | 适用 |
|---|---|---|---|
| L1 | UI 树（AccessibilityNodeInfo） | 最低/最快/最稳 | 常规界面（按钮/文本能被无障碍读到） |
| L2 | OCR（本地 ML Kit / PaddleOCR） | 中 | UI 树读不到的文字（图片字、特效字） |
| L3 | 截图 + VLM | 高/慢 | 复杂、陌生、动态页（战斗结算、新活动） |

## 2. 降级触发条件

- L1 结果"文本/可点元素过少"（< N 个）→ 升 L2；
- L1/L2 无法判定页面归属（所有指纹都不命中）→ 升 L3；
- 任务进入"未知页面"或"新活动页" → 直接 L3；
- 关键操作（领取奖励、结算确认）失败重试后 → L3 复核。

## 3. ScreenState 结构（扩展版）

```json
{
  "page_id": "p_yuhun_select",
  "page_conf": 0.93,
  "elements": [
    {"id": "com.netease.onmyoji:id/btn_start", "text": "挑战",
     "desc": null, "clickable": true, "bounds": "..."}
  ],
  "all_text": ["御魂", "十层", "挑战"],
  "popup": {"detected": true, "type": "activity_notice", "close": "close_x"},
  "loading": false
}
```

## 4. 页面判定

- 用 `PageFingerprint`（must 全含 + any 任一）对 `all_text` 匹配，归因到 `page_id`；
- 多页候选时按"命中 must 数量"打分，取最高且 ≥ 阈值；
- 归因失败 → 交给决策层（AI 兜底）。

## 5. 弹窗检测（独立、优先）

- 弹窗独立于页面判定，**先于一切动作**处理；
- 常见类型：活动公告、广告、回归奖励、断线重连、网络提示、每日首充；
- 每个弹窗在知识库有记录：识别特征 + 关闭方式（右上角 X / "关闭" / "知道了"）；
- 主流程每步执行前先跑"弹窗清场"。

## 6. 元素定位

- 顺序：词典(resource_id) → 文本 → 坐标区域 → VLM 目标检测；
- 与「返回识别器」共用区域/形状识别底座。

## 7. 性能与缓存

- 截图节流：只在关键步或 L3 时才截图，避免每步都调 VLM；
- OCR 结果按"页面指纹"缓存；
- L3 仅在 L1/L2 不足时触发，控制 token 与延迟。
