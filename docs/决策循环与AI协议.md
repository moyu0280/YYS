# 决策循环与 AI 协议详细设计

> Agent 的"脑"：规则状态机为主、AI 兜底。目标：确定步骤快且省，异常/未知交给 LLM。

---

## 1. OODA 循环

```
Observe（读屏）→ Orient（判定页面/进度）→ Decide（选下一步）→ Act（执行）→ 回到 Observe
```

每步都校验"行动是否生效"（页面是否变化）；不生效则重试或换方式。

## 2. 双轨决策

- **规则轨（状态机）**：词典/流程库已覆盖的确定步骤，直接执行，不调 LLM；
- **AI 轨（兜底）**：规则失败、未知页面、新活动页、异常弹窗 → 交给 Brain。

## 3. 轨切换条件

- 规则步骤失败 ≥1 次 → 升 AI 轨（一次性兜底）；
- AI 也无解（返回 null）→ 暂停交人工；
- AI 连续成功处理某类问题 N 次 → 沉淀成规则，降回规则轨（失败学习）。

## 4. 记忆设计

- **短期（工作记忆）**：当前任务已做步骤、当前页面、最近失败原因（单次会话）；
- **长期（账号状态）**：体力/勾玉余量、任务进度、活动进度（SQLite）；
- 记忆只给决策提供上下文，**不跨账号共享**。

## 5. 模型路由

| 场景 | 用谁 |
|---|---|
| 是否加载中 / 是否弹窗 / 页面是否变化 | 规则或本地小模型 |
| 未知页面、新活动、复杂异常 | 云端大模型（多模态） |
| 判定标准 | 输入复杂度 + 是否需看图 + 延迟/成本预算 |

## 6. 完整 prompt 协议（Brain 兜底）

### 系统提示词

```
你是《阴阳师》手游自动化助手，运行在 Android 无障碍环境里。
你只能看到屏幕元素列表（text/desc/id/bounds），不能读内存、不能假设不存在的按钮。
你的目标是安全、准确地推进当前任务的一步。

铁律：
1. 返回上一页只能点左上角箭头，关闭弹窗只能点右上角 X 或"关闭/取消"按钮，禁止任何"系统返回键"。
2. 涉及消耗勾玉/御魂/金币、购买、分解、删除的操作，一律不执行，改为返回 {"action":{"type":"none"},"reason":"需人工确认"}。
3. 不确定时宁可返回 none（交人工），也不要乱点。
4. 只输出 JSON，不要输出任何解释文字。
```

### 每步输入（模板）

```
当前版本：{version}
任务：{task_id}（{task_name}）
当前步骤：{step_desc}
近期已完成：{memory.done}
知识库提示（RAG 片段）：{rag_snippets}
当前屏幕元素：
id=... text=... desc=... clickable=... bounds=...
...
```

### 输出 schema（严格 JSON）

```json
{"action":{"type":"clickText|clickId|clickElement|clickRegion|inputText|back|wait|none",
 "text":"","id":"","elementId":"","x":0.0,"y":0.0,"ms":0},"reason":"..."}
```

- `none` = 无解/需人工，交人工并附 `reason`；
- 其余 type 与 `TaskConfig.Action` 一一对应。

## 7. 失败学习闭环

1. AI 兜底成功解决某异常 → 记录「屏幕特征 → 正确 action」；
2. 同类异常累计命中 N 次 → 固化为词典规则，下次走规则轨；
3. 失败案例同样入知识库，标记"已知坑"，避免重复踩。
