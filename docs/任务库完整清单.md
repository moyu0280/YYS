# 任务库完整清单（全部日常 / 活动）

> 覆盖"一个号的所有日常与活动"。每个任务 = 一段 YAML（DSL）+ 前置条件 + 调度。
> 界面文本/坐标均为**待采集标注占位**，正式版由知识库（领域知识层）填充。

## 2. 代表性 DSL（示例）

### 每日签到（最简）
```yaml
task:
  id: daily_signin
  name: 每日签到
  schedule: daily
  steps:
    - enterPage: p_home
    - action: { clickText: "签到" }
    - action: { wait: 1500 }
    - enterPage: p_signin
    - action: { clickElement: e_signin_claim }
    - action: { back: true }
```

### 御魂副本（带战斗循环）
```yaml
task:
  id: soul_run
  name: 御魂副本
  schedule: daily
  preconditions:
    - { type: stamina, min: 6 }
  steps:
    - enterPage: p_home
    - action: { clickText: "探索" }
    - action: { clickText: "御魂" }
    - enterPage: p_yuhun_select
    - action: { clickElement: e_yuhun_layer10 }   # 选择十层
    - action: { clickElement: e_yuhun_start }     # 挑战
    - enterPage: p_battle
    - action: { clickElement: e_auto_battle }     # 开启自动
    - waitFor: { page: p_reward, timeout: 300000 } # 等结算（VLM 判定）
    - action: { clickElement: e_reward_close }    # 右上角 X
  loop: { times: 3 }                              # 刷 3 次（可配置）
  fallback_ai: "结算页/失败页处理：..."
```

### 悬赏封印（遍历+领取）
```yaml
task:
  id: bounty
  name: 悬赏封印
  steps:
    - enterPage: p_home
    - action: { clickText: "悬赏封印" }
    - enterPage: p_bounty_list
    - action: { clickElement: e_bounty_claim_all }  # 一键领取
    - action: { back: true }
```

### 限时活动（模板 + AI 兜底）
```yaml
task:
  id: event_template
  name: "当前限时活动"
  schedule: activity_period
  template: true                    # 走"模板 + AI"快速适配
  steps:
    - enterPage: p_home
    - action: { clickElement: e_event_entry }   # 活动入口（版本特性表定位）
    - ai: "根据当前活动页，完成可领取/可挑战项；涉及消耗则跳过"
  fallback_ai: "活动页异常时：截图交给 VLM 理解后决定"
```

## 3. 页面流转总览（主界面 → 各玩法）

```
主界面 p_home
 ├─ 签到/召唤/体力        → p_signin / p_summon / p_mail
 ├─ 悬赏封印              → p_bounty_list
 ├─ 结界                  → p_kekai → 突破 p_breakthrough / 寄养 p_foster
 ├─ 探索                  → p_explore → 御魂 p_yuhun_select / 觉醒 p_awaken
 ├─ 逢魔之时              → p_fengmo
 ├─ 阴阳寮                → p_guild → 捐赠 / 任务
 └─ 活动入口（版本动态）   → p_event_*
```

> 每个页面的 fingerprint / 元素 / 返回方式由知识库 `page` 与 `ui_element` 表维护，版本更新时自动保鲜。

---

## 4. 优先级分期

- **P0（MVP 先跑通）**：签到、领体力、悬赏、御魂、结界突破 —— 确定性最高、风险最低；
- **P1**：觉醒、御灵、探索、百鬼、寮捐赠/任务、逢魔、式神委派；
- **P2**：秘闻、地域鬼王、限时活动（模板 + AI）；
- **默认关闭**：斗技、协同斗技、一切消耗勾玉/御魂/金币的操作。
